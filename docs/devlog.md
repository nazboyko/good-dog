Everything local was green because the local toolchain is 1.26 and CI reads go-version-file from go.mod, so the one hand written copy of the version was the only one that could be wrong, and it was. make toolchain-check now compares the two and fails before a deploy does, which turns a round trip through Fly into a one line message.
- Production found the compression thing I reported wrong, and a real bug under it. My curl probe did not advertise Accept-Encoding, so the bundle looked like it shipped uncompressed at 170KB; the browser's own performance entries show 64KB of brotli. Same class of mistake as the JSON parse error two days ago: the tool doing the measuring was the thing that was broken. The real find was that GET / served index.html with no Cache-Control at all, while every unknown route set no-cache. Two paths serve the same file and only the one nobody hits was protected, and index.html is what points at assets marked immutable for a year, so a copy cached before a redeploy asks for a bundle the redeploy deleted.
- Scoped the fix to index.html rather than every non asset file. The scene webps have no ETag and go:embed gives them a zero modtime, so no-cache on them means refetching 515KB with nothing to revalidate against. The narrow fix is provably zero blast radius; the wide one trades a stale page risk for a bandwidth one.
- The night had three dogs talking at once. The server paces cues on offsets tuned for reading and a spoken line runs about twice its slot, so each voice started on top of the last. Fixed as a queue rather than a timer: arrivals buffer, each line waits for the one before it to finish plus a 700ms beat, and lines with no voice keep the old reading pace so the muted night is the night it always was. Measured in the browser afterwards by wrapping the Audio constructor and recording start and end of every element: zero overlaps across fourteen lines, gaps of 703 to 706ms, and the night grew from 25 seconds to 52, which is exactly the overlap that used to be there.
- Two words meant two different things and that was the whole bug. "Done" meant the server finished sending, and it was also what unlocked sleep. Those are not the same moment once audio outlives the schedule. The stream handler is onAllSent now and only the queue decides the night is over.
- Gate 1 sent it back twice and was right both times. Every queue test handed all three cues over synchronously, so the queue never ran dry between arrivals, which is the state a real night spends most of its time in: deleting `draining = false` and deleting the `sealed` check both passed 17 of 17. And the test named "only finishes when the sound does" called end() before it ever awaited, so a play() that resolved the instant playback started, which is the original overlap bug restored, passed too. Three load bearing behaviours with guards that could not fail. Eight mutations are checked now instead of three.
- The sleep button was already disabled in the DOM the whole time. There was no :disabled rule anywhere in the stylesheet, so a genuinely unavailable button looked identical to a live one, and the honest reading of that is a button that ignores you. It now loses its ground and goes dashed, and the label already said why. One exception written down: the vocalization buttons go unavailable for the half second an answer is in flight and then fade out, and dressing that as unavailable reads as a fault of its own.
- The dog can be heard. Pressing a vocalization was the only thing the player ever does and it happened in silence, so five sound effects now play the instant a button goes down, ahead of the round trip and ahead of the answer: you hear what you did, then you read how it landed. Pregenerated like everything else, silence deliberately silent.
- The guardian failed the first draft over one word. "A low quiet warning growl" contradicts the game's own line for that button, "not yet, give me a moment", and warning was the word most likely to return a snarl. That is not pedantry: a grumble read as "maybe not this one" teaches the player how little it takes to lose a home, and a snarl read the same way tells them the visitor was right. One adjective decides which of those two games this is. Whine lost "pleading" and howl lost "mournful" for the same reason, both of them pre-loading the visitor's reading into the sound the player made. Also caught that two prompts said medium sized dog and three did not, which is five different animals, which is a soundboard.
- Two cache key bugs found by review, same shape both times. The key hashed the prompt but not the duration, then the prompt and duration but not the generation settings one package over. Either way, retune the thing and make voices reports a warm cache while the game plays the old file for good. The settings now go through a SoundSettings function so the key moves when the sound would, and changing the influence from 0.7 to 0.05 fails the test instead of silently doing nothing.
- Gate 1 found the fifth surviving mutation on the unit whose whole premise is ordering: moving bark after the await inverted the feature and 50 of 50 tests passed. The call site had no coverage at all, only bark in isolation. That needed jsdom, which the project did not have, so it has it now for the one test that clicks a real button and holds the answer open forever. Two more the same day: a hand copied vocalization list that could not see a seventh button, and a 404 test whose 404 came from an empty directory rather than from the handler. That one is fixed by planting the file the handler must never reach.
- Also fixed something no test would have caught: bark was fire and forget, so a three second howl played straight through the beat of dark between screens, and on the reduced motion path, where every transition is instant, it played over the reveal.
